# B 反馈处理：既有结果的补充分析（2026-11-09）

以下数字由已验收的 11/7 数据重新计算，不是本轮新集群实验。新的排除节点、整节点基线及优化实验尚未取得有效结果。

## 术语和比较单位

- **MMS（制造解方法）**：先给定解析解，再由方程生成 RHS 和边界，用于独立检验数值程序。
- **rank**：一个独立 MPI 进程；**halo**：保存邻居旧解的边界副本。
- **warmup（预热）**：按同一配置启动一次但不进入正式统计。
- **measurement batch（实验批次）**：有共同硬件/设置的一组运行；旧稿的 cohort 指这个含义。
- **same-allocation MPI reference（同分配 MPI 基准）**：同一资源分配中、同问题及总核数的纯 MPI 时间；不是任取一条扩展曲线的点。
- **PE（处理单元）**：此处为分配给一个 rank 的物理 CPU 核。
- **MPI_THREAD_FUNNELED**：MPI 只由初始化 MPI 的主线程调用，其他线程只做本地计算。
- **NUMA（非一致内存访问）**：内存位于不同 CPU 插槽/节点，访问本地和远端内存的成本可不同。首次触碰实验检查初始化方式的影响，不将其直接等同于已测得页分布。

## 128³ 的扩展饱和

P36/P72/P288 的中位数分别为 0.336666/0.337059/0.294310 s。P36 到 P288 使用 8 倍核心，仅快约 12.6%；两个前点的范围重叠。局部点数约由 5.8 万降为 0.73 万，面/体积比上升，固定消息和同步开销更容易主导；节点数也由 1 变为 3/9，不能只归因于 P。256³ 的对应时间为 2.740522/1.238393/0.632244 s；512³ 的 P72/P288 为 9.755425/3.273120 s，大工作量更能摊薄开销。现有分阶段计时针对 256³，不把其百分比冒充 128³ 的实测占比。

## 72 核混合变慢的可检验机制

旧实现只在线程并行区内分担更新；面打包/解包和 Sendrecv 由主线程串行执行，其他线程等待。减少 rank 虽可降低总消息数，却增加每 rank 的面尺寸，串行准备可能拉长关键路径。每轮重新进入 OpenMP 区域也有团队进入/同步成本。

绑定日志显示单个 rank 的线程通常位于一个插槽；因此“主线程首次触碰导致跨 NUMA 远端访问”不是已证明的原因。首次触碰、缓存共享、单线程打包和线程管理需要分别控制。本轮同一新二进制的 baseline/parallel_pack/first_touch/persistent/optimized 五种运行方式用于拆分这些因素；原始二进制作为额外参考，防止把容器/代码生成差异错归给优化。仅有当前数学检查，没有集群性能结果，尚不能说哪一项已带来收益。

## 三套单线程基线

| 实现 | 128³秒 | 256³秒 | 设置 |
|---|---:|---:|---|
| A 串行 | 4.709857 | 39.009305 | CN-161，GNU12.2/-O2，无 MPI/OpenMP，单核绑定 |
| B MPI P1 | 5.010988 | 45.525023 | GN-A40-074，共享分配 ncpus=2，实际 1 rank/1 核，GNU12.2/OpenMPI4.1.5 |
| C CPU1 | 6.330078 | 51.450687 | GN-A40-024，NVHPC24.7/GCC13.2 工具链，OpenMP 单线程持久区域 |

三者的代码、循环/存储表达、运行时和分配不同。A/B 同为 GNU12.2，不能把所有差距归给编译器；C 的 CPU1 仍有 OpenMP 控制结构。历史 2D 更新量归约解释不能直接移植到当前无逐轮归约的 3D 核心。本轮已准备同一整节点、同一核、同编译设置的 A/B 对照和向量化报告；没有测量前不声称已找到唯一原因。

## 对 144 核结论的修正

原批次和后续四节点复跑共同包含 CN-011、CN-108；因此只能叫共享节点的复跑，不能作为节点独立性证据。原 144 核 128³/256³/512³ 时间只增长约 1.4 倍，而点数增长 64 倍；结合约 97.7% 通信/等待占比，支持“大固定等待项”的观察，不直接证明硬件故障。

原 144 核混合 1.79–2.03 倍收益是相对高等待 MPI 基准的条件性观测，尚不能代表正常节点上的混合优势。应以新的不重叠四节点分配给混合布局建立自己的纯 MPI 参考；九节点×16 的纯 MPI 点不能拿来作四节点×36 混合的分母。
